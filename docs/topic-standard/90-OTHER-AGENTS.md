# 90. Запуск конвейера в других ИИ-инструментах (Gemini, Kimi, DeepSeek и др.)

> **Назначение модуля**: адаптер для выполнения конвейера [`00-PIPELINE.md`](00-PIPELINE.md) в ИИ-инструментах отличных от Qwen Code. Стандарты, роли и нормы здесь **не дублируются и не переопределяются** — описана только разница механики запуска.
>
> **Для Qwen Code ничего не меняется**: штатный вход — [`../../TOPIC_CREATION_PROMPT.md`](../../TOPIC_CREATION_PROMPT.md), роли — именованные субагенты `.qwen/agents/`.

## 1. Что переносимо, а что привязано к Qwen Code

| Составляющая | Переносимость | Эквивалент в другом инструменте |
|---|---|---|
| Модули стандарта, паспорта, реестр констант (Markdown на диске) | ✅ полная | Те же файлы — чтение с диска |
| Регламенты ролей `topic-verifier.md` / `topic-proofreader.md` | ✅ полная | Тело файла (всё после YAML-frontmatter) — самодостаточный промпт роли; frontmatter (`name`, `description`, `tools`) — служебные метаданные Qwen Code, другими инструментами игнорируется |
| Автозагрузка контекста из `QWEN.md` | ⚠️ частичная | Контекстный файл инструмента: `GEMINI.md` / `AGENTS.md` (шимы в корне репозитория, §3) |
| Запуск именованных субагентов (`agent` tool) | ❌ нет | Новая изолированная сессия с телом роли (§4) |
| Токен-дисциплина про форки Qwen Code | ❌ нет | Общее правило: ролевые задачи — **всегда** новая сессия с чистым контекстом, никогда не продолжение сессии разработчика |

## 2. Матрица инструментов

Требования ролей: верификатору обязателен веб (≥ 2 источника на утверждение), постпроверке обязателен shell (`npm run build && npm run lint`, `node scripts/audit-formulas.mjs` как часть гейта), разработчику — файлы, shell и git.

| Инструмент | Тип | Полный конвейер | Режим |
|---|---|---|---|
| Gemini CLI | Агентный CLI (файлы, shell, веб) | ✅ да | §4.1, §6.1 |
| Kimi CLI | Агентный CLI (файлы, shell) | ✅ да | §4.1, §6.2; наличие веб-доступа проверить в своей версии — без него верификатор работает по §7.1 |
| DeepSeek (чат) | Чат без доступа к файлам и shell | ⚠️ частично | §4.2, §6.3 — ручной режим: оператор выполняет файловые операции и гейты |
| DeepSeek-модель в агентной обвязке (aider, Cline, OpenCode, Roo Code и т.п.) | Агентная обвязка | ✅ да | §4.1 через `AGENTS.md` |

## 3. Файлы-шимы автозагрузки контекста

В корне репозитория лежат шимы, перенаправляющие на единый контекст `QWEN.md`:

- [`GEMINI.md`](../../GEMINI.md) — читает Gemini CLI;
- [`AGENTS.md`](../../AGENTS.md) — читают Kimi CLI и большинство агентных обвязок (Codex, Cursor, Cline, OpenCode, …).

Шимы сознано не дублируют сводку: единственный источник нормы — `QWEN.md` и модули стандарта. Если инструмент не читает ни один из шимов, содержимое шима и `QWEN.md` вставляется первым сообщением в сессию координатора.

## 4. Запуск ролевых агентов: изолированный контекст

Требования конвейера неизменны (00-PIPELINE §1): верификатор и постпроверка работают с чистым контекстом, сами читают стандарты и файлы темы по путям из задания, сами пишут полный отчёт на диск и возвращают координатору **только вердикт** (≤ 20–30 строк). Вердикты блокирующие.

### 4.1 Шаблон А — агентный инструмент с доступом к файлам

Роль запускается **новой сессией** (отдельное окно/процесс, не продолжение сессии разработчика) с текстом:

```
Прочитай файл .qwen/agents/topic-verifier.md — весь текст после YAML-frontmatter —
и работай строго по нему: это твой полный регламент.

Рабочий каталог: корень репозитория S_Chem_Portal.

Задание: научная верификация черновика теории новой темы.
Тема: <название>
Семейство: <ХЭ-NN | ОХ-NN>
Паспорт темы: docs/topic-passports/<slug>.md
Черновик теории: <путь/пути к черновику>
Реестр констант: docs/topic-passports/reports/verified-constants.md

Формат результата:
1. Полный отчёт запиши на диск:
   docs/topic-passports/reports/<slug>-verification-report.md
   (формат — в регламенте роли).
2. В ответе — только вердикт (≤ 20–30 строк): статус, счётчики утверждений,
   список блокирующих расхождений с требуемыми исправлениями, путь к отчёту.
```

Для постпроверки тот же шаблон с заменой ролевого файла на `.qwen/agents/topic-proofreader.md`; в задании указываются папка темы `src/components/study/topics/<topicSlug>/` и затронутые файлы регистрации. Постпроверка сама выполняет `npm run build && npm run lint` и `node scripts/audit-formulas.mjs` как часть гейта и сама пишет `docs/topic-passports/reports/<slug>-postcheck-report.md`.

### 4.2 Шаблон Б — чат без доступа к файлам (DeepSeek)

1. Открыть **новый** чат (не продолжать прежнюю беседу).
2. Вставить тело ролевого файла без frontmatter, затем задание текстом: содержимое черновика теории и паспорта (или прикрепить файлы), строки реестра констант, относящиеся к теме.
3. Включить веб-поиск, если доступен: верификатору нужны ≥ 2 независимых источника на утверждение.
4. Оператор сам сохраняет полученный отчёт в `docs/topic-passports/reports/<slug>-verification-report.md` и передаёт строки вердикта в сессию координатора.

Постпроверка в чате: оператор вставляет файлы темы, локально выполняет `npm run build && npm run lint` и аудит формул, вставляет вывод в чат; роль проверяет только предоставленный текст и вывод гейтов.

## 5. Сессия координатора-разработчика

Первое сообщение в агентном инструменте (Gemini CLI / Kimi CLI / обвязка):

```
Работаем в репозитории S_Chem_Portal. Прочитай QWEN.md и соблюдай его полностью.

Создай новую учебную тему по конвейеру docs/topic-standard/00-PIPELINE.md.

Тема: <название, напр. «Кремний и его соединения»>
Семейство: <ХЭ-NN (химия элементов) | ОХ-NN (общая химия)>
Подгруппа/элементы/раздел: <напр. «IV-A, неметаллы»>
Особенности (опционально): <акценты, отклонения, пожелания>

Отличия от порядка TOPIC_CREATION_PROMPT.md:
1. Ролевые агенты (шаги 1 и 7 конвейера) запускаются не именованными
   субагентами, а по docs/topic-standard/90-OTHER-AGENTS.md §4 (шаблон А).
   Если инструмент умеет сам стартовать изолированную сессию/субагента —
   используй это; иначе остановись и попроси оператора запустить вторую
   сессию по шаблону А и вернуть вердикт.
2. Токен-дисциплина: ролевые задачи — никогда в этой сессии; стандарты читать
   с диска выборочно по «карте чтения» 00-PIPELINE; большие файлы регистрации —
   только поиск по blockId/id и чтение фрагментом.
```

Координатор не начинает разработку до вердикта верификатора «0 критичных расхождений» и не коммитит до вердикта постпроверки «0 critical» — как и в штатном конвейере.

## 6. Особенности инструментов

### 6.1 Gemini CLI
- `GEMINI.md` читается автоматически при старте — шим уже в репозитории.
- Роли: каждая новая сессия — чистый контекст; верификатора и постпроверку запускать в отдельных сессиях по шаблону А.
- Веб-доступ для верификатора — встроенные веб-инструменты инструмента; если веб отключён, действует §7.1.

### 6.2 Kimi CLI
- Если версия читает `AGENTS.md` — шим уже в репозитории; иначе вставить шим + `QWEN.md` первым сообщением сессии координатора.
- Роли — новые сессии по шаблону А.
- Наличие веб-доступа у верификатора проверить в своей версии/конфигурации.

### 6.3 DeepSeek (чат)
- Официального агентного CLI нет; чат не имеет доступа к файлам репозитория и shell.
- Реалистичная зона: черновик теории, научная верификация (шаблон Б), текстовая часть постпроверки. Сборка кода, регистрация, гейты и коммит — на операторе либо в агентном инструменте.
- Полная альтернатива: DeepSeek-модель в агентной обвязке (aider, Cline, OpenCode, Roo Code и т.п.) — такая связка читает `AGENTS.md` и способна на полный конвейер по шаблону А.

## 7. Ограничения и неизменные требования

1. **Верификатор без веб-доступа не принимает тему**: утверждения, которые не удаётся подтвердить источниками, помечаются в отчёте «источник недоступен» и считаются блокирующими; в вердикте отсутствие веба указывается явно.
2. Гейты (`npm run build`, `npm run lint`, `node scripts/audit-formulas.mjs`) выполняются там, где доступно окружение репозитория: в агентном инструменте — самим агентом, в чат-режиме — оператором.
3. Коммит (шаг 9 конвейера) — только после подтверждения оператора; `git push` без явного запроса оператора не выполняется.
4. Критерий готовности темы не меняется: оба отчёта на диске в `docs/topic-passports/reports/`, 0 critical, гейты чистые, паспорт актуализирован.
